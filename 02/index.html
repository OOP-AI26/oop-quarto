Class Attribute

Class attribute adalah data yang dimiliki oleh class, bukan dibuat khusus untuk setiap object.

class Produk:
    jumlah_produk = 0

    def __init__(self, nama):
        self.nama = nama
        Produk.jumlah_produk += 1

a = Produk("Mouse")
b = Produk("Keyboard")

print(a.nama)              # Mouse
print(Produk.jumlah_produk)  # 2

Intinya: jumlah_produk dipakai sebagai penghitung bersama, bukan milik satu object saja.

  • Bedakan self.nama dengan Produk.jumlah_produk.
  • self.nama berbeda untuk setiap object.
  • jumlah_produk berada pada level class sehingga satu counter dipakai bersama.
  • Dalam study case, counter rekening dan counter setoran adalah contoh class state.

Playground 1 — Class State

Jalankan dulu, lalu coba:

  • amati perubahan counter melalui object maupun melalui class.
  • Jalankan dulu tanpa mengubah kode.
  • Tanyakan: mengapa totalnya 3 padahal tidak ada self.jumlah_produk?
  • Arahkan mahasiswa untuk melihat bahwa increment dilakukan pada class Produk.
  • Tantangan kecil: tambahkan satu object lagi dan prediksi output sebelum Run.

Constructor: Tempat Object Dilahirkan

Constructor __init__ dipanggil otomatis setiap kali object dibuat.

class Buku:
    def __init__(self, judul, halaman):
        self.judul = judul
        self.halaman = halaman

buku = Buku("Algoritma", 300)

Alurnya:

Buku(...) → __init__(...) → object siap digunakan

Constructor cocok untuk inisialisasi object, memastikan object lahir dalam kondisi awal yang valid.

  • Bedakan self.nama (object state) dengan class attribute.
  • Constructor bertugas membuat object berada dalam kondisi awal yang valid.
  • Study case memakai constructor untuk nama, nomor, dan saldo awal.

Factory Method dengan @classmethod

Kadang object perlu dibuat dari format input tertentu. Daripada parsing di luar class:

teks = "Python;2026"
bagian = teks.split(";")
buku = Buku(bagian[0], int(bagian[1]))

kita sediakan factory method di dalam class:

class Buku:
    @classmethod
    def dari_teks(cls, teks):
        judul, tahun = teks.split(";")
        return cls(judul, int(tahun))

buku = Buku.dari_teks("Python;2026")

Factory method = cara alternatif untuk membuat object.

  • Kata kuncinya adalah “factory”: method ini menghasilkan object.
  • cls menunjuk ke class yang memanggil method.
  • return cls(...) membuat object melalui class tersebut.
  • Ini membuat parsing dan konstruksi object tetap dekat dengan class yang bertanggung jawab.

Playground 2 — Factory Method

Perhatikan tiga langkah di dalam method: pecah teks → ubah tipe data → buat object dengan cls.

  • Tunjukkan bahwa caller tidak perlu tahu bagaimana string diparsing.
  • Tekankan cls, bukan Buku, pada return.
  • Modifikasi latihan: ubah format menjadi "C++;2025".

@staticmethod: Method Tanpa Object

Static method cocok untuk operasi yang:

  • berhubungan dengan class,
  • tetapi tidak membutuhkan self,
  • dan tidak membutuhkan cls.
class Kode:
    @staticmethod
    def valid(kode):
        return kode.startswith("B") and len(kode) == 4

Kode.valid("B123")  # tidak perlu membuat object Kode
  • Bandingkan dengan classmethod: staticmethod tidak menerima cls.
  • Validator biasanya merupakan contoh yang mudah karena hanya memeriksa input.
  • Study case memakai pola yang sama untuk memeriksa nomor rekening.

Playground 3 — Static Method

Coba ubah beberapa input dan lihat hasil validasinya.

  • Jelaskan bahwa method ini dapat dipanggil langsung dari class.
  • Perhatikan bahwa tidak ada self.
  • Hubungkan dengan study case: nomor valid jika pola tertentu terpenuhi.

Property: Attribute yang Punya Aturan

Tanpa property, barang.stok = -100 bisa saja terjadi begitu saja.

Dengan property, assignment melewati validasi terlebih dahulu:

class Barang:
    @property
    def stok(self):
        return self.__stok

    @stok.setter
    def stok(self, nilai):
        if nilai < 0:
            raise ValueError("Stok tidak boleh negatif")
        self.__stok = nilai
  • Jelaskan bahwa property membuat assignment terlihat seperti attribute biasa.
  • Di belakang layar, getter dan setter adalah method.
  • __stok adalah penyimpanan internal.
  • Dalam study case, __saldo menjadi internal state dan saldo menjadi interface yang dikontrol.

Getter dan Setter: Alur Sederhana

barang.stok = 20 → setter → validasi → __stok
barang.stok      → getter → __stok
  • Menulis barang.stok = 20 → Python menjalankan setter.
  • Menulis barang.stok → Python menjalankan getter.

Property = kontrol akses state tanpa mengubah cara pemakaian dari luar.

  • Ini konsep penting sebelum decorator.
  • Pengguna class tidak perlu tahu nama __stok.
  • Setter adalah tempat yang tepat untuk invariant sederhana seperti batas minimum/maksimum.
  • Assignment di dalam __init__ juga melewati setter — penting untuk validasi saldo awal.

Playground 4 — Property & Validation

Coba: ubah stok awal, lakukan assignment baru, perhatikan kapan ValueError muncul.

  • Jalankan versi awal.
  • Ubah barang.stok = 35 menjadi nilai negatif untuk melihat validasi.
  • Tekankan bahwa assignment ke self.stok di constructor juga melewati setter.

Apa Itu Decorator?

Decorator adalah fungsi yang membungkus fungsi lain, menambahkan perilaku tanpa menulis ulang fungsi asli.

fungsi asli → decorator → fungsi yang sudah dibungkus
def sapa_dulu(func):
    def wrapper():
        print("Sebelum")
        hasil = func()
        print("Sesudah")
        return hasil
    return wrapper
  • Gunakan analogi pembungkus, tetapi jangan terlalu lama pada analogi.
  • Fungsi asli tetap ada, tetapi reference-nya digantikan dengan wrapper hasil decorator.
  • Decorator sangat berguna untuk perilaku tambahan seperti logging, counting, timing, dan validasi.

Decorator dan *args/**kwargs

Masalah muncul jika kita tidak tahu signature function yang akan dibungkus:

func(a)
func(a, b)
func(a=10)
func(a=10, b=20)

Solusi umum pada wrapper:

def decorator(func):
    def wrapper(*args, **kwargs):
        hasil = func(*args, **kwargs)
        return hasil
    return wrapper

*args menampung positional, **kwargs menampung keyword arguments — keduanya diteruskan lagi ke function asli.

  • Tekankan bahwa *args/**kwargs menjaga wrapper tetap fleksibel.
  • Di study case, method dipanggil dengan keyword argument jumlah=....
  • Karena itu wrapper harus meneruskan kwargs, bukan hanya args.

Playground 5 — *args/**kwargs

Function dapat dipanggil dengan positional maupun keyword arguments.

  • Jalankan dan perhatikan bentuk tuple pada args dan dictionary pada kwargs.
  • Hubungkan dengan pemanggilan method pada starter code.
  • Tantangan: panggil total(a=10, b=20, bonus=5) dan amati perubahan args serta kwargs.

Decorator yang Mengubah Hasil

Decorator tidak hanya menambahkan output — decorator juga bisa mengubah return value.

def jadi_boolean(func):
    def wrapper(*args, **kwargs):
        hasil = func(*args, **kwargs)
        return bool(hasil)
    return wrapper
0     → False        "yes" → True
1     → True         ""    → False
  • Bedakan “menjalankan function” dengan “mengubah hasil function”.
  • bool(hasil) adalah inti decorator jenis ini.
  • Dalam study case, decorator hasil_boolean memastikan hasil setor menjadi True/False.

Playground 6 — Transform Return Value

Decorator ini mempertahankan *args/**kwargs, tetapi mengubah return value.

  • Tanyakan apa yang terjadi jika function asli mengembalikan 2, -1, atau "".
  • Tekankan bahwa decorator tidak perlu mengubah isi cek_nilai.

Decorator untuk Mencatat Percobaan

Sekarang kita tambahkan efek samping: setiap kali function dipanggil, sebuah counter bertambah.

def catat(func):
    def wrapper(*args, **kwargs):
        hasil = func(*args, **kwargs)
        Sistem.percobaan += 1
        return hasil
    return wrapper
call → func asli → counter + 1 → return hasil

Yang dihitung adalah percobaan memanggil function, bukan hanya keberhasilan.

  • Ini persis pola penting untuk study case.
  • Jangan tertukar antara “attempt” dan “success”.
  • Setoran gagal tetap merupakan satu percobaan sehingga counter harus tetap bertambah.

Decorator Chaining

Kita bisa memakai lebih dari satu decorator sekaligus:

@catat
@jadi_boolean
def cek(...):
    ...

Cara membacanya (dari dalam ke luar):

cek → jadi_boolean → catat → wrapper paling luar

Secara konsep: cek = catat(jadi_boolean(cek)) — urutan decorator penting.

  • Jelaskan aturan praktis: decorator yang paling dekat dengan function diterapkan terlebih dahulu.
  • Untuk study case, hasil_boolean membungkus method asli, lalu catat_setoran membungkus hasil tersebut.
  • Tidak perlu membahas descriptor atau detail bytecode.

Playground 7 — Chaining

Kode di bawah menggunakan dua decorator sekaligus. Coba ubah urutan decorator dan amati perilakunya.

  • Pastikan mahasiswa menjalankan sebelum memodifikasi.
  • Minta mereka membaca dari decorator paling bawah ke atas.
  • Tekankan bahwa counter tetap naik pada nilai 60 karena function tetap dipanggil.

Method yang Mengubah State

Validasi dulu, mutasi kemudian — jangan lakukan self.saldo += jumlah sebelum validasi selesai.

class Dompet:
    def __init__(self, saldo):
        self.saldo = saldo

    def tambah(self, jumlah):
        saldo_baru = self.saldo + jumlah

        if jumlah <= 0:
            return False
        if saldo_baru > 500000:
            return False

        self.saldo = saldo_baru
        return True
input → cek aturan → valid? → ya: update state / tidak: state tetap

Prinsip: validasi dulu, mutasi kemudian — ini membuat aturan state jauh lebih mudah dilacak.

  • Ini pola yang akan langsung dipakai untuk method setor.
  • Perhatikan bahwa state hanya diubah setelah semua validasi lolos.
  • Jika gagal, return False dan saldo tidak disentuh — ini mencegah state object menjadi tidak valid.
  • Mahasiswa sering melakukan assignment terlalu awal lalu mencoba “membatalkan”. Lebih sederhana menghitung candidate state terlebih dahulu.
  • Property setter juga menjadi lapisan pengaman tambahan.

Playground 8 — State + Validation

Contoh lengkap dengan batas saldo.

  • Jalankan: 300 + 150 berhasil menjadi 450.
  • Penambahan 100 gagal karena melewati 500. Perhatikan saldo tetap 450 setelah kegagalan.
  • Tantangan: ubah batas atau jumlah agar mendapatkan kasus tepat di batas.

Parsing Input & String Validation

Starter code memiliki alur seperti ini:

nama, nomor, saldo, jumlah = input().split()
teks = f"{nama} {nomor} {saldo}"
tabungan = Tabungan.dari_teks(teks)
main → input → factory → parsing + konversi → constructor → object

Main program tidak perlu tahu detail pembuatan object. Validator nomor rekening pada study case memiliki aturan: A + tepat 4 digit, dipecah menjadi kondisi kecil:

def valid(kode):
    return (
        len(kode) == 5
        and kode[0] == "A"
        and kode[1:].isdigit()
    )
  • Hubungkan factory method dengan starter code — main hanya mengatur alur, detail parsing berada di factory.
  • Untuk validasi string, pecah requirement menjadi tiga pertanyaan: panjangnya benar? karakter awal benar? sisanya digit?
  • Contoh: A1001 valid, A07 tidak valid, B4004 tidak valid.
  • Kode ini adalah contoh konsep, bukan implementasi yang harus disalin mentah untuk study case.
  • Jangan memindahkan atau mengubah main program jika requirement meminta main tetap dipertahankan.

Playground 9 — Parsing & Validation

Contoh berbeda dari study case, tetapi pola berpikirnya sama.

  • Kode ini sengaja memakai prefix K dan 5 digit, bukan aturan nomor rekening.
  • Minta mahasiswa menjelaskan tiga kondisi dalam return.
  • Modifikasi prefix menjadi P, atau ubah panjang menjadi aturan lain dan prediksi output.

Checklist Sebelum Submit

Kerjakan bertahap: struktur dasar → utility → decorator → business logic, lalu jalankan test case satu per satu.

Contoh cara baca test case: saldo 900000 + setoran 200000 > batas 1000000 → setor gagal, saldo tetap 900000, tapi percobaan tetap dihitung.

  • Gunakan checklist ini setelah kode selesai.
  • Fokus pada invariant: counter, saldo, dan return value.
  • Ajarkan mahasiswa membaca test case sebagai urutan state transition; bedakan “gagal” dengan “tidak dihitung” — counter setoran tetap naik meskipun transaksi gagal.

  • Minta mahasiswa membuat satu perubahan yang dapat diamati dari output.
  • Jangan fokus pada “jawaban benar”; fokus pada hubungan perubahan kode dengan state object.
